# Known-failing "path config" pairs for tests/run_examples.sh, one per
# line, path relative to the repo root, config is "on" or "off".
#
# Each entry below was individually diagnosed (not just observed) when
# this file was seeded -- see the reason on each line. None of these are
# fixed here; they are Phase-1 (or, where noted, Phase-2) work.

# --- Infinite-run examples: sc_start() with no stop time and no code
# path that ever halts the simulation. Not a hang in the SystemC sense
# and not stdin-blocked (checked); the model is simply unbounded as
# written. Needs an explicit stop condition or a duration argument.
ct/cttutorial on
ct/cttutorial off
mi/ir_uwb_radar on
mi/ir_uwb_radar off

# --- D15 fixed in step 0.6: the FMU-description XML parser
# (XmlElement/XmlParser/XmlParserCApi) is now vendored into
# src/forsyde/fmi2/ and libxml2-linked, and is confirmed working end to
# end -- it unzips fmi2/car.fmu and correctly parses fmiVersion=2.0,
# modelName=car out of its modelDescription.xml. What blocks "on" now is
# purely on the GDB side, and it comes in two layers depending on the
# environment:
#
#  1. On a machine where GDB genuinely cannot get a controlling terminal
#     (confirmed here: installing xterm did not fix this -- gdbwrap's
#     spawned xterm opens and immediately shows only
#     "warning: GDB: Failed to set controlling terminal: Operation not
#     permitted", then hangs forever). That is a sandbox restriction
#     (this machine runs a locked-down dev sandbox), not a missing
#     package, and it produces a real, visible, un-closeable window --
#     three of them accumulated across three routine test runs before
#     this was caught. tests/run_examples.sh now refuses to run this one
#     config at all when FORSYDE_SKIP_GDB is set in the environment,
#     rather than letting it hang and open another window; set that
#     permanently on any host where a GDB session cannot get a real
#     controlling terminal.
#  2. On a host where GDB attaches cleanly (untested from here; plausibly
#     true on an ordinary CI VM runner, not confirmed), the run still
#     doesn't complete: fmi2/car.fmu is a Co-Simulation-only FMU (no
#     ModelExchange element in its XML), but whatever sim_support.h code
#     path this wrapper drives requires ModelExchange -- "error: No
#     ModelExchange element found in model description. This FMU is not
#     for Model Exchange." A real defect in ct_wrappers.hpp /
#     sim_support.h's FMU-loading logic, in the wrapper code itself
#     rather than the parser.
#
# Both are natural fits for the Phase 1b wrapper rework (explicit time
# contract, rebuilt on CoPrep/CoApply/CoProd) rather than standalone
# patches here. Also newly observed, not yet its own line item: gdbwrap
# does not kill its spawned `gdb --interpreter=mi` child on any exit
# path, confirmed on both the hang and the successful-attach case --
# only its own clean()/destructor can fix that, not this test harness.
#
# The "off" configuration does not hit any of this: this harness
# produces the "off" build by overriding CFLAGS wholesale, which also
# strips this example's -DFORSYDE_WITH_GDB -DFORSYDE_WITH_FMI, so it
# silently takes the non-wrapper code path instead. That is a
# limitation of this interim harness, not evidence the "off" build is
# exercising the wrapper path safely.
mi/cruisecontrol on

# --- Invalid macroblock grid: fsr=176, fsc=44, bs=8 in globals.hpp --
# 44 is not divisible by 8, so the frame is not a whole number of
# macroblocks. In the non-introspective build this aborts outright
# (SIGABRT). In the introspective build it does not crash, but two
# consecutive runs of the identical binary produce different output --
# confirmed directly, not inferred -- consistent with the same invalid
# grid causing an out-of-bounds or uninitialized-memory read that
# happens not to trip an assertion here. Neither configuration's output
# can be pinned to a golden file until this is fixed. A fix (frame size
# expressed in terms of nmb, corrected to 64x64) already exists on the
# wip/mp4dec-scenarios branch.
sadf/mp4dec on
sadf/mp4dec off

# --- DEFINE_TYPE_NAME / DEFINE_TYPE used directly in example code
# (types.hpp is only included under FORSYDE_INTROSPECTION, so these
# macros are undefined in the "off" build and the calls parse as

# Same defect class as the library's own D2/D3 header-hygiene issues,
# just found in example code instead of src/forsyde.
